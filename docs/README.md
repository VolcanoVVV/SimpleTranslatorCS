# 汉化工具链：规划与接手入口

更新日期：2026-09-19。

## 当前任务与结论

用户希望将 SimpleTranslatorCS、ConfigurationManager.zh-cn 汉化工作台、SPT ID 提取工具连接起来，形成“提取原文 → 自动初译 → 人工校对 → 保存覆盖 → 游戏内刷新”的工作流，并保留 SPT 4.0 / 4.1 支持。

**可实施。推荐统一操作入口、分离执行职责：**

- SimpleTranslatorCS 负责服务端文本目录、覆盖、版本适配、保存和管理接口。
- ID 提取器的 Core 提供离线扫描与候选来源；桌面 GUI / CLI 继续独立可用。
- zh-cn 工作台增加“服务端游戏文本”数据源，与现有“客户端配置文本”并列。
- 增加可选的轻量客户端桥接模块，负责游戏 locale 拉取、客户端缓存与界面刷新；完整编辑 UI 复用工作台。
- 自动翻译优先在发起操作的工作台/桌面端执行；服务端核验结果后决定保存与发布。无客户端需求仍可使用 CLI。

以上为推荐方案，不表示相关接口或客户端插件已经存在，也不表示用户已经确认所有产品细节。

## 接手时优先牢记

- 4.1.2 的 LazyLoad 没有 Clear；本机 4.1.3 有缓存和 Clear。按能力适配，不只判断“是否 4.1”。
- zh-cn 的刷新现在只调用 ConfigurationManager.BuildSettingList，不刷新 EFT 全局 locale。
- 提取器 Core 是 net8.0；zh-cn 是 .NET Framework 4.7.1 / Unity Mono，不能直接把 Core DLL 放进客户端使用。
- 离线扫描找不到所有运行时生成文本；运行时拿到一个键也不能自动证明它属于哪个 mod。
- Global、Menu、Dialogue、客户端配置项是不同命名空间，不能用一个裸字符串 key 混合去重。
- 机器初译、人工译文、覆盖生效、客户端刷新是不同状态，不能用一个“已完成”概括。
- 当前 SimpleTranslatorCS 会递归扫描翻译目录；草稿、报告、历史和 manifest 必须放在活动翻译目录以外。
- 下一阶段默认先做“基础正确性 + 只读条目目录”，不要直接把扫描、网络翻译、热刷新全部塞进 OnLoad。

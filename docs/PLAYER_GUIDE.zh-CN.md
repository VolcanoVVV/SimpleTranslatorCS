# SimpleTranslatorCS 玩家、服主与二次开发手册

适用服务端源码版本 **1.5.0**。配套 F12 和独立网页工作台为 2.14.1。安装 ZIP 根目录的 `README.zh-CN.md` 可作为快速入口。

## 先选安装方式

| 想做的事 | 需要安装 |
| --- | --- |
| 让服务器加载现成的物品、任务、商人和对话译文 | 对应 SPT 版本的 SimpleTranslatorCS |
| 在游戏内管理服务器译文、发起翻译、校对和同步 | SimpleTranslatorCS、匹配运行时的 ConfigurationManager 和 ConfigurationManager.zh-cn |
| 单独翻译 F12 插件设置 | 客户端 ConfigurationManager 和它的汉化插件 |
| 在无图形界面的服务器修改术语 | 服务端加任意 UTF-8 文本编辑器 |

| 服务器 | 服务端 ZIP | 配套客户端运行时 |
| --- | --- | --- |
| SPT 4.0.x | 文件名含 `SPT-4.0` | Mono |
| SPT 4.1.x | 文件名含 `SPT-4.1` | Mono |
| SPT 5.0 BE | 文件名含 `SPT-5.0be`，核对 BE 构建 | IL2CPP |

### 安装和升级

1. 停止服务器，备份现用 Mod 目录。重点保留 `translations/`、旧 `db/locales/ch/`、`glossary/eft.zh-CN.tsv`、`config.jsonc`、`workbench-admin.jsonc`、`translation-providers.jsonc` 和 `cache/` 中的基准及待审记录。
2. 找到已有 `user/mods` 的目录。常见路径为游戏目录下的 `SPT` 或 `SPT_Runtime`，以本机实际安装为准。将 ZIP 的 `user` 解压到这里。
3. 确认 `user/mods/Volcano-SimpleTranslator/SimpleTranslatorCS.dll` 存在，检查 Mod 目录是否还有相同插件的旧副本。若手工覆盖升级，对照合并新版样例 `config.jsonc` 和已有配置。
4. 启动服务端，用日志确认 Mod 加载和语言表写入。游戏语言选择中文。更换 DLL 后完整重启相应程序。只改普通译文可用管理员重载，有运行时差异或对话变更时按工作台重启提示处理。
5. 使用发布页提供 SHA256 时，可用 PowerShell 的 `Get-FileHash -Algorithm SHA256 -LiteralPath <ZIP路径>` 对照所下载 ZIP 的同名记录。

## 手工安装和制作译文

以下目录均相对于服务器上的 SimpleTranslatorCS Mod 目录。

| 路径 | 用途 |
| --- | --- |
| `translations/ch/` | 普通译文统一放在这里。新保存的文件名为 `模组名_API.jsonc`（AI）、`模组名_MT.jsonc`（机翻）或 `模组名_Manual.jsonc`（人工） |
| `translations/ch/dialogue/` | 对话专用文件，键为对话文本 ID。旧 `Manual/dialogue/` 仍可读取 |
| `translations/ch/Manual/`、`API/`、`MT/`、`_workbench/` 和 `db/locales/ch/` | 旧路径原位读取。新版保存普通译文时直接写入 `translations/ch/` |
| `glossary/eft.zh-CN.tsv` | 服务端 AI 用词参考 |
| `cache/` | 原文基准、文件开关、审核、备份或报告等运行状态 |

普通译文用 UTF-8 JSON 或 JSONC。顶层是一个对象，键和值各为字符串，值可以用 JSON 转义表示换行。下面是格式示例，示例键需要替换为从自己的服务器确认的真实键。

```jsonc
{
  // 键按实际运行时语言表填写
  "example.item Name": "示例物品",
  "example.item Description": "此处保留原文中的 {0} 和 %s。"
}
```

- 从工作台目录、原版运行时数据或可信的离线提取结果确认原始键。真实键的大小写、字段后缀都照抄；4.0 普通表大小写敏感，4.1/5.0 BE 普通表采用不区分大小写的比较，对话仍应照抄精确键。
- 同键优先级仍为人工 > AI > 机翻。类型由旧目录或文件名后缀识别，普通无后缀文件按人工处理。同类型先读旧 `db/locales/ch`、再读当前目录中保留旧布局的文件，最后读带类型后缀的根目录文件。旧 `_workbench` 生成文件先于同类型的旧分层文件。其余同组文件按相对路径排序，后读的同键覆盖先读的。冲突可查启动日志和开发报告。
- 工作台按服务器识别的模组目录名拆分写入。原版或未能归属的词条归入 `原版游戏_*.jsonc`，独立的其他语言表文本归入 `其他语言表文本_*.jsonc`。特殊字符或过长名称会转换成可保存的文件名。旧文件可留在原处，后续补译和校对都使用新布局。
- `dialogue` 是独立的对话数据表。翻译器只把已有对话元素认得的文本 ID 写入中文语言槽位。仅取得 Global 键不能证明它是对话键。对话改动后重启服务器并重新连接。
- 普通译文的未匹配新键仍可写入中文表。只有游戏或 Mod 也引用了该键，文本才会显示。草稿、生成报告、来源文件和不用的备份应存放在活动译文目录以外，避免被扫描。
- 可使用旧 `db/locales/ch` 的字典文件。旧版 3.11 的 C# 以外 Mod 代码和新版 DLL 各有自己的运行环境，迁移时应复制译文文件。

## 在工作台操作

启动已装配套客户端的游戏后，打开 **汉化工作台 → 服务端游戏文本**。服务器从内置 `/client/locale/ch` 提供发现标记，工作台随后确认能力。板块不显示时先确认选对服务器、服务端 DLL 加载成功、两边支持相同工作台协议，再用客户端的重新检测入口。

### 服主与译者

1. 在服务器本机取 `workbench-admin.jsonc` 中的 `adminKey`。填到管理员栏并验证，看到通过提示后再开始写操作。首次启动会尝试生成独立的密钥文件。改动此文件后重启服务器。
2. 打开 AI 或机器翻译页，读取供应商配置。选择来源和少量待翻条目，核对模型、服务器访问的接口主机与费用。
3. 按需填写自己的平台 API 密钥及应用 ID。接口测试可能发送一条真实请求并产生费用；首次测试使用小范围。模型自动获取失败时可手输模型 ID，在玩家模式下还要符合服主管理的白名单。
4. 发起后查看任务进度、已保存和未通过数量。已通过的批次逐批保存。取消会保留已完成批次。修好配置后刷新目录，从仍缺失的条目开始续翻。
5. 校对已生成译文或审核玩家投稿。正式译文发布后，新版客户端收到变更通知再请求增量，空闲无需固定轮询。现有客户端画面可能需要重开页面；对话仍按重启提示处理。

### 普通玩家和 Fika

普通玩家可按服务器规则获取已发布译文。**未检测到 Fika** 且服务器允许玩家贡献时，有效玩家会话可提交人工或网页回填候选，或在服主明确开放玩家 API 时自费生成候选。审核批准后才进入正式译文层。**检测到 Fika** 时，本版常规服务端工作台操作要求管理员密钥，已发布译文的只读同步和访问验证按各自条件工作。玩家遇到权限提示可联系服主。

管理员密钥与 AI 平台密钥分别使用。服务端任务会把平台密钥交给当前服务器发请求，请确认服务器和供应商可信。普通玩家处理完只在本机 F12 设置中生效的翻译使用客户端自己的配置和术语表。

### 术语和费用

服务端 AI 任务读取服务器的 `glossary/eft.zh-CN.tsv`。首次读取时可用 example 初始化；现用文件存在时会保留。只把当前原文命中的词条附加到提示词，预算受词条数和字符数限制，编辑后下一次任务生效。编辑、预览及已发布译文同步不产生模型调用。若已有译名需要纠正，可直接人工校对。详细格式和离线工具操作见 [术语表手册](GLOSSARY_EDITOR.zh-CN.md)。

AI 请求次数与 token 预算会在发出之前检查。估算值用于限制下一次请求，供应商报告的实际用量用于回算。模型账单以供应商为准。频繁超时先查网络和模型状态；看到 429 可检查额度、间隔和模型。可将自动重试设为 0。HTTP 413 会按现有规则尝试拆小批次，有可能增加请求次数。

## 读懂服务器启动与任务日志

| 提示 | 含义 | 下一步 |
| --- | --- | --- |
| 绿色「覆盖已有键」 | 该键已存在于英文参考表或当前中文基底，合并后有一个胜出译文 | 用同键在游戏中抽查 |
| 青色「新增键」 | 胜出键在两张基底中都未找到 | 核对实际引用、Mod 是否加载和键名 |
| 黄色「部分覆盖／未覆盖已有键」 | 有新增或有同键竞争，或该文件所有键都未覆盖基底 | 看每行的覆盖、新增和被同键覆盖计数 |
| 绿色「已写入语言表」 | 本 Mod 已执行启动时普通译文的合并写入 | 游戏未显示时检查语言、页面缓存及其他 Mod 的后续覆盖 |
| 绿色「对话已写入」 | 对话译文进入匹配到的中文槽位 | 重新进入当前游戏会话抽查 |
| JSON/JSONC、权限或 HTTP 错误 | 某一步骤读写或调用失败 | 按同一行指示查语法、文件访问或供应商状态 |

控制台颜色由 SPT 宿主和终端决定。复制到纯文本或终端不支持颜色时，仍可按标签判断。启动的「尝试读取」包含启用但空白或读失败的文件，和成功写入键数是两个不同的数量。

- 服务器控制台有启动、对话、文件监听和工作台审计消息。审计附会话摘要、角色与结果。常规只读通知或差量拉取不会在本 Mod 审计中反复打印。
- `API翻译日志/SimpleTranslatorCS/` 在游戏根目录、SPT 服务端根目录或独立 Mod 位置，由运行路径决定。按日的 `.operations.jsonl` 是操作日志；`.errors.jsonl` 收录失败、异常、拒绝和部分完成；任务编号的 `.json` 含进度、词条结果、请求次数、已报告 token 和中文状态；`.inputs.jsonl` 含请求前记录的原文与提示词。
- `config.jsonc` 中 `devMode: true` 启用词条报告和文件变更提醒。默认报告 `cache/reports/translation-report.jsonc`，查看键所属文件、竞争和占位符。报告可能含原文、译文或本机路径，提交问题前请筛除私密信息。
- JSON 报错行号从 1 开始，行内字节偏移从 0 开始。中文字符的 UTF-8 字节数可能多于一个字符。另存为 UTF-8 并检查对象括号、成对引号、错误逗号、重复键与非字符串值。

## 原理和二次开发

启动时服务器读取配置，准备活动与兼容目录，把普通 JSONC 合并成中文键值快照并挂进 SPT 的语言表构建流程。占位符在合并后解析，可以引用其他文件导入的物品名称。对话单独写入匹配元素。工作台以运行时加载的英文和中文表、实体领域和当前翻译状态构造目录，生成的翻译需要通过原文、标记和权限校验才会发布。新增覆盖或撤销会更新版本并让客户端按需读取差量。

第一次二次开发可从一个小的人工翻译包开始：

1. 拷贝一组你拥有授权的小型 JSONC 样例到测试目录，以实际运行时键填一条。只改值，保留占位符、富文本、路径、快捷键、数字和换行结构。
2. 在隔离的 SPT 目录加载，检查启动颜色和开发报告，随后到游戏对应页面抽查。不改 DLL 时包里可以只交付译文字典和使用说明。
3. 若要增加自动翻译领域，先确认数据表和键确实存在，再追加领域规则、来源归属、回归测试。服务端 Global、对话与客户端 F12 是不同数据来源。
4. 若要移植 DLL，先用构建目标验证 SPT 接口和数据结构，再核对懒加载缓存重建、覆盖恢复、对话 ID 和权限行为。各目标 DLL 单独发布。

可以让 AI 帮你解释某条启动日志、检查 JSONC、初译可公开的一小段原文、起草适配补丁和测试。开一个干净的源码副本，提供目标 SPT 版本、相关函数路径、脱敏日志、几条可复现条目和可接受的行为。先让 AI 指出实际读取和写入位置，再查看它提交的差异。只在测试服及样例文件上试跑，生产数据、私人原文、会话和所有密钥由维护者自己保管。

示例请求：

> 目标 SPT 4.1。请先阅读项目 AI 接手指南和现有 JSONC 测试。用给出的三条样例复现日志里的语法报错，保留条目 ID 和占位符。只改测试用译文，给出加载命令、预期日志和我应该核对的游戏页面。

字段、接口和移植细节见 [AI 与开发者接手指南](AI_MAINTAINER_GUIDE.zh-CN.md)。版本选择遵循 [版本号约定](VERSION_POLICY.zh-CN.md)。

## 如何反馈

注明 SPT 的准确版本、服务端安装包名及修订日期、配套客户端版本、是否检测到 Fika、重现步骤和预期结果。附服务端日志相关片段和能够公开的小样例。现有译文、术语、用户档案、真实会话 ID、管理员密钥、API 密钥和包含私人文本的输入日志需先脱敏。

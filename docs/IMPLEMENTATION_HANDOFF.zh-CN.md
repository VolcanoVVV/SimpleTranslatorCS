依赖：S1。

- [ ] ST-005 单个 transformer 读取不可变快照；注册次数不随保存增长。
- [ ] ST-006 4.0/4.1.2 无缓存路径、4.1.3 可清缓存路径；英文 fallback 不长期捕获过期启动字典，也不能在同语种 transformer 中递归读取自己。

- [ ] SAVE-001 草稿、校验、历史、原子 generation、活动引用、坏文件保留旧快照。
- [ ] API-002 validate/commit/remove/reload/history/rollback，修订冲突、幂等重试、管理权限。
- [ ] RL-001 watcher 去抖、失败重试、删除/重命名、溢出重扫、退出释放；与 API 发布共用串行入口。

MVP 只在验证的 Global 模式声明支持热加载。Dialogue 仍保持既有启动行为，界面明确提示暂不支持在线应用，直到对应任务验收。

### S3：最小游戏内编辑与刷新闭环

依赖：S2 + SP-001。

- [ ] WB-001 zh-cn 抽出工作台模块注册、数据源、保存和刷新适配；保持配置汉化不回归。
- [ ] CL-001 独立可选 Client 桥接；获取实际服务器连接，握手能力/权限；工作台缺失时有最小刷新入口。
- [ ] WB-002 “服务端游戏文本”页：按 mod/类别搜索，原文/当前值/编辑值，保存和删除自有覆盖。
- [ ] CL-002 异步取数、主线程应用、按已验证 UI 通知、刷新合并和断连降级。
- [ ] CL-003 区分服务端已应用、客户端缓存已更新、界面待重开三个状态。

验收：从工作台修改一条物品名 → 服务端持久化 → 下一次 locale 请求新值 → 主菜单客户端数据与至少一个指定界面更新 → 删除覆盖恢复下层。整个流程不要求重启服务端。客户端不支持热刷新时保存仍可用并正确提示降级。

这是第一个可交给用户试用的端到端里程碑，先人工编辑，再加自动翻译，便于定位问题。

依赖：S3（桌面/CLI 方向可先连接 S2）。

- [ ] TR-001 抽出通用任务/指纹/校验及三协议适配；保留机翻接口能力并注明各前端支持情况。

- [ ] TR-005 原文新增/改变/删除/未观测状态；按层暂停已知过期译文，保存历史而非删除人工成果。

验收：模拟服务测试所有支持协议；占位符/标签/必要数字/换行被改写时拒绝提交；取消不保存当前未完成包；修改设置只影响下次任务；重启后可按有效指纹复用；后台翻译期间人工修改不会被旧任务覆盖。

不要求用户提供真实付费密钥才能做自动化验证。真实提供商联调由用户配置后单独进行，并记录所用协议而非仅服务商名字。

## 4. 验收矩阵

| 场景 | 应有结果 |
| --- | --- |
| 旧 JSONC + 无客户端插件 | 现有翻译正常，用户无需迁移 |
| Global 和 Dialogue 同名 key / 不同 mod 同名 key | 作用域不混淆；实际写入位置的冲突仍可见 |
| 多文件互相引用物品名 | 基于完整合并结果解析，不由枚举先后决定 |
| 大小写不同 key | 与具体版本目标字典一致地诊断，不静默分裂 |
| 动态新增文本、无法归属 mod | 条目可观测，来源置信度如实显示 |
| 删除/禁用/重命名翻译包 | 撤销本包覆盖，恢复下层，不残留旧 transformer |
| 坏 JSONC、文件暂被占用、磁盘写失败 | 保留旧活动快照；报告真实保存/应用状态 |
| API 保存与 watcher 同时触发 | 串行、去重，不无限循环发布 |
| 4.1.3 第三方直接写缓存 | 不宣称无条件兼容；按已验证模式保留、适配或禁用该重载方式 |
| AI 返回漏键/多键/重复键/非字符串 | 拒绝该批次发布 |
| `${id}` 的 `$` 或 `|short` 丢失、标签嵌套改变 | 验证失败，即使 JSON 合法也不发布 |
| 自动任务遇到来源冲突、低置信度 | 跳过并标为待核对，不强行自动覆盖 |
| AI 执行时源文或人工层被修改 | 提交冲突，保留人工修改及候选草稿 |
| 同一提交超时重试 | 同幂等键返回同一结果，不重复发布 |
| 服务器重启、版本回退、客户端断连 | 实例/快照重新握手，保留上次有效本地文本 |
| 游戏内保存成功但 UI 未更新 | 显示真实刷新级别，不误报失败或全量成功 |
| 普通远程玩家请求写入/使用管理员翻译额度 | 权限拒绝；不影响正常读取语言 |
| 仅装 zh-cn、不装 SimpleTranslatorCS | 原有配置汉化全部可用，服务端页隐藏或显示未连接 |
| 翻译器库依赖未随 dist 发布 | 发布验收应发现缺失，不能只检查编译成功 |

测试分四层：纯逻辑单测 → 模拟提供商/管理协议测试 → 实际 SPT 服务器集成 → 实际 Unity 客户端 UI 验收。一个层级通过不能替代后一个。

## 7. 给下一位 AI 的接手指令

可复制以下内容作为下一次开发请求：

> 请先阅读 SimpleTranslatorCS/docs/README.md、PROJECT_INVENTORY.zh-CN.md、INTEGRATION_DESIGN.zh-CN.md 和 IMPLEMENTATION_HANDOFF.zh-CN.md。当前只有规划文档，没有完成三项目集成。请检查当前 git diff 和实际源码，以文件现状为准。默认先开展 S0 的基础正确性修复，并以小型验证确认客户端刷新入口；如果本次只授权服务端代码，则先做 ST-001 至 ST-004，将客户端验证记录为后续任务。保留旧 JSONC 和 4.0/4.1 构建。每个完成项更新验收证据，不把设计接口当作已实现 API，不把 BuildSettingList 当作 EFT locale 刷新。不要自动调用付费接口或部署到游戏目录。

接手操作顺序：

1. 阅读本机适用 AGENTS.md、git 状态和用户最新要求；这些文档不能覆盖用户后续指示。
2. 确认三个仓库位置、目标程序集版本及当前任务写权限；外部两个项目可能需要调整工作区权限。
3. 明确本次只做哪些任务 ID，先补关键失败用例，再进行小范围实现。
4. 引入新项目时检查 SDK 默认源文件扫描、obj/bin 隔离、依赖打包、版本元数据及 Unity 公共程序集重复加载。
5. 验证完成后记录命令、版本、结果和未覆盖场景，再更新状态。不要仅因为代码能编译就勾选游戏内验收。
